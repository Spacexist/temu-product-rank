Part 1 · 给人看

1. 一句话

这是一个筛子，不是一个预言机。

你每天有几千个家居厨房新品。模型按「看起来会不会卖」排序。你只人工看前 5%。历史数据里：

  • 随便翻：100 个品里大约 22 个卖得出去。
  • 模型挑的前 5%：100 个里大约 55 个卖得出去。
  • 换成「用前两天训练、去挑第三天新品」这种更接近真实用法的测法：100 个里大约 54 个卖得出去，相对基线大约是 2 倍（从 2.5 倍掉到 2 倍）。

它帮你把几千个品压成两三百个值得花两秒看一眼的。它不会告诉你哪个会爆。前 20 名里也曾出现过 4 个零销量。

2. 现在怎么用

  1. 永远按比例取，不要设分数线。正确说法：「今天这批的前 5%」。错误说法：「预测分大于 1.0 就上」。分数没有校准过。
  2. 只看家居厨房。三个训练文件的一级类目 100% 是「家居厨房用品」。
  3. 主图拉不到的品单独挑出来人工看，不要扔。流水线会静默丢掉主图失败的行。历史里这 432 个品动销率 74.3%，平均销量 15.7，是整批最高的。
  4. 不要把店铺信息喂给模型。候选品最终都进同一家店（你的店），店铺变量对排序本来就没贡献。
  5. 预期下调到 2 倍，不要还按 2.5 倍想。2.5 倍是三天混合、按店铺切开的成绩。
  6. 试卖才能回答「搬到我店能不能卖」。 离线实验学的是这个品在原来那家店卖得怎么样。

4. 模型在干什么

每件商品变成三块信息：

  1. 主图：ResNet18 看成 512 个数字（图像指纹）。
  2. 标题：中文向量模型 BGE-small-zh 看成 512 个数字（语义指纹）。
  3. 商品属性：价格、有没有视频、轮播图张数、标题长度、中文占比、类目等。不含任何店铺信息。

训练目标不是「卖或不卖」，而是：把总销量先压到训练集的 99.5 分位（大约 46 件），再取 log(销量 + 1)。这样 4900 件那种极端爆款不会把训练带偏。分数越大表示越可能卖得多。使用时按分数从高到低排，取前 5%。

7. 能信 / 不能信 / 已知坑

能信

  • 在未见店铺上，比瞎挑强大约 2～2.5 倍。
  • 类目内部也比基线强（厨房收纳基线 12%，模型挑中的 94%）。
  • 按天外推掉 20%，但没有崩。未见店铺子集几乎不掉。
  • 指标偏保守：被丢掉的无图好品没进测试集。

不能信

  • 「搬到我店里也会卖。」没有跨店同品证据。
  • 「观察窗口已经核实是 8 天。」只有 2.25% 的行能算，而且全是正例。
  • 「14% / 43% 就是大店红利。」那是两个模型的预测能力差，不是因果。
  • 「外测 80%～86% 说明模型更准。」那个文件本身就有 61% 在卖。相对基线只有约 1.3 倍。
  • 文件名 source 当特征：给新一天打分时它是没见过的类别。
坑后果日常怎么躲
主图失败直接丢行丢掉动销率 74% 的好品拉不到图的单独人工看
910.csv / 911.csv 其实是 xlsxread_csv 必崩三个文件都用 read_excel
系统 python 是 CPU 版 PyTorch极慢或对不上环境必须用 F:\Clip\venv\Scripts\python.exe

8. 目标与禁区

任务：对 SKU 按预期销量排序，支撑「每天从新品里取 top 5% 人工看」。

训练目标（必须按这个，不要改成二分类）：

y = log1p( clip(总销量, 0, p99.5_train) )
  • p99.5 只在当前训练集上算。店铺切分时是 46.0；按天切分（909+910）时是 45.63。
  • 不要设「销量 > N」当 label。
  • 不要用曝光天数去除销量。分子冻结在快照、分母算到「今天」会让同一份数据每天换标签。

禁止进入 full 的列：店铺 ID / 店名 / LOGO / 店铺评分 / 店铺总销量 / 粉丝数 / 在售商品数 / 托管模式；总销量、日周月销量、GMV、美区评分、美区评论数；收录时间；名为「上架时间」的抓取时刻；cat_l1（全表常量）。

店铺ID 只允许用于 GroupShuffleSplit 分组。LEAK_shop 可以临时拼上四个店铺规模列，报告必须标明不可部署。

14. 评测

k = max(1, int(np.ceil(n * 0.05)))
top = np.argsort(-pred)[:k]
prec = (sales[top] > 0).mean()
lift = prec / (sales > 0).mean()

阈值：>0、>=5、>=20。这些是报告口径，不是训练目标。

配对 slate：每个 K 只生成一次；只在同一 source 内抽样；所有组共用同一 slates；random 用另一个 default_rng(SEED+1)。断言：同一 K 下所有组的 rand 和 oracle@1 必须精确相同。不要把 random lift@5 ∈ [0.85, 1.15] 当硬门槛。lift@1 可写入 json，不要写进给人看的主表。

跨组比较必须报「×基线」，禁止只报绝对 P(>0)。

17. 硬性验收

  1. 同一 K 下所有组 rand、oracle@1 精确相同。
  2. y 的构造含 clip(..., p99.5)，分位数来自当前 train。
  3. full 特征里没有店铺列、没有收录时间、没有美区评分、没有销量/GMV。
  4. cat_l1 不在特征里。
  5. 给人看的表没有 lift@1；第一张表是全量 top 5%，且带 ×基线。
  6. 按天跑时 CAT_COLS 不含 source。
  7. 打印无图丢弃行数，以及有图/无图的销量>0 率。

18. 明确不要做的事

  • 不要把外测文件的绝对 P(>0) 和域内 55% 并列成「外测更好」。
  • 不要写「大店红利 = XX%」或「搬店后不会复现 XX%」。
  • 不要把 676 行子集的窗口分布写成全量事实。
  • 不要为了让 random lift 落进某个区间去换种子。
  • 不要在复现当前数字的同时「顺手」改丢图逻辑、加校准、改 LightGBM 参数。
